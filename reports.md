# mse1h2026-judge0
## О проекте
Проект предполагает интеграцию системы judge0 на замену текущей coderunner, для тестирования ее работы и совместимости с moodle.

### Постановка задачи
Интеграция и тестирование judge0 в локальном контейнере moodle на нескольких задачах.

### Требования
#### Системные требования
- **Docker** (версии 20.10 или выше)
- **Docker Compose** (версии 2.0 или выше)
- Не менее 4 ГБ оперативной памяти.

### Сценарии использования
Создание задач по программированию и автоматическая их проверке

### Инструкция по запуску
#### Развертывание контейнеров
- Перейдите в корневую директорию проекта, затем в директорию moodle_docker
 ```bash
   cd mse1h2026-judge0/moodle_docker
   ```
- Выполните команду для сборки всех контейнеров
```bash
   docker compose up -d
   ```
- Выполните скрипт инициализации
```bash
  chmod +x init.sh
   ./init.sh
   ```
#### Настройка плагина в Moodle
- Откройте браузер и перейдите по адресу: [http://localhost](http://localhost).
- Авторизуйтесь под учетной записью администратора:
   - **Логин:** `admin`
   - **Пароль:** `bitnami1`
- Перейдите в раздел управления плагинами: `Администрирование` -> `Плагины` -> `Установка плагинов`.
- Нажмите **"Обновить базу данных Moodle"**.

#### Подключение Judge0
- В Moodle перейдите: `Администрирование` -> `Плагины` -> `Типы вопросов` -> `Judge0` (или `Настройки Judge0`).
- Найдите поле **URL сервера Judge0**.
- Впишите туда сетевое имя контейнера Judge0:
   ```text
   http://server:2358
   ```

#### Проверка работоспособности среды
Дополнительно в проектом имеется Bash-скрипт, который автоматически проверяет, все ли поднялось корректно.
Выполните:
```bash
bash tests/test_environment.sh
```

### Выполненные задачи

2) Разработка PHP-клиента для REST API Judge0 (метод `send_judge0_request()`)
3) Реализация базового MVP: «Студент → Проверка → Результат» — полный цикл данных через Judge0
4) Портирование механизма «Шаблонов» из CodeRunner (`checker_code` — код конкатенируется с решением студента)
5) Интеграция UI-макетов в формы Moodle (форма преподавателя, табличный рендеринг результатов)
6) Написание автоматизированных тестов окружения (`test_environment.sh`, `test_judge0_api.py`, `test_plugin_acceptance.py`)
7) Создание «Инструкции по запуску» (в `reports.md`)

### Дополнительные фичи
8) Выбор языка программирования — с 10 языками (Python, C++, Java, JS, C#, Bash, Ruby, Rust, Kotlin, PHP)
9) Множественные тест-кейсы — таблица `qtype_judge0_testcases` с `repeat_elements`, весами, скрытыми тестами
10) Частичное оценивание — оценка = сумма весов пройденных / суммарный вес
11) Идеальное решение — автоматический расчёт `expected_output` через запуск эталонного кода
12) Генератор уникальных входных данных — скрипт-генератор с seed = Moodle User ID
13) 3-фазный конвейер проверки: [Генератор] → [Идеальное решение] → [Решение студента]
14) Табличный UI результатов — таблица с колонками: Тест / Ввод / Ожидалось / Ваш вывод / Статус
15) Скрытые тесты — данные ввода/вывода заменяются на «Скрыто» для is_hidden тестов
16) Страница настроек админки (`settings.php`) — настройка URL Judge0 через интерфейс
17) Русская + английская локализация плагина
18) Устранение дублирования запросов к Judge0 в renderer (данные кешируются при оценивании)

### Задачи на следующую итерацию
1) Переход на асинхронную модель проверки  — уход от блокирующих HTTP-запросов, которые могут зависнуть при нагрузке
2) Кеширование результатов генератора и идеального решения — сейчас при каждом просмотре попытки возможен перерасчёт; нужно сохранять в `question_attempt_step_data`
3) Добавить файл `db/upgrade.php` — миграции БД для обновления плагина на существующих инстансах Moodle без сброса данных
4) Батчевые запросы к Judge0 — отправлять все тест-кейсы одним batch-запросом (`/submissions/batch`), а не по одному, для ускорения проверки
5) Портирование реальных задач с курса алгоритмов из CodeRunner в формат Judge0 — демонстрация обратной совместимости
6) Подсветка синтаксиса — интеграция Ace Editor или CodeMirror для подсветки кода в зависимости от выбранного языка
7) Расширенные настройки лимитов по задаче — преподаватель задаёт cpu_time_limit, memory_limit, max_processes на уровне каждой задачи (сейчас используются дефолты Judge0)
8) Горизонтальное масштабирование Judge0 — конфигурация нескольких worker-нод, балансировка нагрузки, тестирование под многопользовательской нагрузкой
9) Обновление и расширение тестов — покрытие новых фич в `test_plugin_acceptance.py`
10) Подготовка демо — создание 3–5 задач различной сложности (простой ввод-вывод, функции, классы, генератор + идеальное решение) для презентации
